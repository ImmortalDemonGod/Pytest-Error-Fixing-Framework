## Provisional intent (to be refined in Stage 4)

PROVISIONAL: This project is an AI-powered automated pytest test fixer. Its purpose is to take a Python repository with failing pytest tests and, without human intervention, generate correct fixes for each failure and submit them as pull requests. The system discovers failures with pytest, formulates LLM prompts (via OpenRouter/LiteLLM) using an analyze-before-fix pipeline, applies code changes with full backup/restore safety, verifies fixes by re-running pytest in a clean subprocess, and creates git branches and pull requests for successful fixes. A secondary feature generates property-based tests using Hypothesis (and optionally LLMs) for untested Python source files. The long-term aspiration visible in the design documents and ai-manager-ideas submodules is to approach SWE-Bench-level autonomous software engineering — automatically finding and fixing real bugs in Python codebases with high accuracy, competing with systems like Aider. Stage 4 refinement should validate whether the SWE-bench framing is still active or if the project has pivoted to a narrower tool-assisted developer-workflow scope.

## Architecture summary

The repository contains two main subsystems sharing the src/ package layout.

Subsystem 1 — Branch Fixer (primary, feature-complete):
Package: src/branch_fixer/
Layers: config/ → core/ → services/ → orchestration/ → storage/ → utils/

Control flow: CLI entry (main.py → run_cli.py fix command) → CLI.setup_components() instantiates all services (AIManager, PytestRunner, ChangeApplier, GitRepository, StateManager, SessionStore) → PytestRunner.run_test() runs pytest in-process via PytestPlugin hooks, capturing TestResult objects → process_pytest_results() converts SessionResult to TestError domain aggregates (working on structured SessionResult objects rather than parsing raw pytest tracebacks, though it still regex-matches each test's error_message string to derive the error type) → CLI.process_errors() iterates errors interactively or non-interactively → CLI.run_fix_workflow() per error: (1) creates a git fix branch via BranchManager, (2) delegates to FixOrchestrator.fix_error() which is a temperature-bumping retry loop (max_retries times), (3) each iteration constructs a FixService and calls attempt_fix(): validate workspace → AIManager.generate_fix() (LiteLLM/OpenRouter, persistent conversation thread per error, analyze-before-fix at temperature=0.1) → ChangeApplier.apply_changes_with_backup() strips fences, writes file, syntax-checks, AST assert-guard, restores on failure → PytestRunner.verify_fix() subprocess pytest for clean env → restore backup if failed, retry with higher temperature → on success, optionally PRManager creates pull request and pushes branch.

Storage layer: FixSession (dataclass in orchestrator.py) tracks session state, persisted via SessionStore (TinyDB, sessions.json). StateManager validates FixSessionState transitions (lowercase enum). RecoveryManager provides checkpoint/restore. CoordinationError and WorkflowDispatcher are async stubs not wired into the live path.

Parser subsystem (services/pytest/parsers/): CollectionParser and FailureParser parse raw pytest string output; UnifiedErrorParser coordinates them. These are superseded in the live path by process_pytest_results() which works directly on SessionResult objects.

Subsystem 2 — Test Generator (Feature 2, DDD-structured):
Package: src/dev/test_generator/
Layers (DDD): core/models.py (domain) → analyze/ (anti-corruption parse layer) → generate/ (application + infrastructure strategies) → output/ (infrastructure write layer) → verify/ (infrastructure verification layer)

Control flow: CLI entry (dev/cli/generate.py generate command) → GenerationOrchestrator.run() → _ensure_importable() adds src/ to sys.path → ModuleParser (AST NodeVisitor) parses source into ParsedModule of TestableEntity objects → select_variants() (pure function in analyze/extractor.py) maps entity type/name to GenerationVariant list → per entity/variant: HypothesisStrategy.generate() calls 'hypothesis write' subprocess using venv-local binary (Path(sys.executable).parent/'hypothesis'), fix_generated_code() post-processes (removes duplicate self args), write_attempt() persists to output_dir → Optional hybrid mode: ContextGatherer gathers mypy/ruff/coverage context, FabricStrategy.generate_module() calls LLM via LiteLLM for two-phase (analyze → write) consolidated module test. VerificationRunner runs pytest on generated tests as subprocess; GeneratedTestFixer uses AIManager+ChangeApplier to repair failures.

Original implementation: scripts/hypot_test_gen.py is a self-contained monolith that was refactored into the DDD structure but remains as a runnable fallback.

CI/CD: ci.yml runs lint→typecheck→security (non-blocking)→test+coverage→integration (non-blocking) on push/PR to main. deploy.yml deploys MkDocs docs to GitHub Pages. docstr-coverage.yml measures docstring coverage.

Stubs: coordinator.py (async SessionCoordinator), dispatcher.py (async WorkflowDispatcher) are placeholder source modules; dev/cli/fix.py, dev/shared/{git,logging,testing}.py, and generate/strategies/pynguin.py are truly empty (0-line) files reserved for planned future features.

Test organization: tests/ has unit/ (mocked dependencies, covers all source modules), integration/ (real subprocess/hypothesis), and test_generator/ (covers dev/test_generator/ subsystem). pytest.ini excludes integration marker by default; CI runs integration separately.
