Follow the Pre-test analysis first then write the tests

Pre-Test Analysis

  1. Identify the exact function/code to be tested
  2. Copy the target code and read it line by line
  3. Note all parameters, return types, and dependencies
  4. Mark any async/await patterns
  5. List all possible code paths
  6. Analyze Infrastructure Requirements
  7. Check if async testing is needed
  8. Identify required mocks/fixtures
  9. Note any special imports or setup needed
  10. Check for immutable objects that need special handling
  11. Create Test Foundation
  12. Write basic fixture setup
  13. Test the fixture with a simple case
  14. Verify imports work
  15. Run once to ensure test infrastructure works
  16. Plan Test Cases
  17. List happy path scenarios
  18. List error cases from function's try/except blocks
  19. Map each test to specific lines of code
  20. Verify each case tests something unique
  21. Write and Verify Incrementally
  22. Write one test case
  23. Run coverage to verify it hits expected lines
  24. Fix any setup issues before continuing
  25. Only proceed when each test works
  26. Cross-Check Coverage
  27. Run coverage report
  28. Map uncovered lines to missing test cases
  29. Verify edge cases are covered
  30. Confirm error handling is tested
  31. Final Verification
  32. Run full test suite
  33. Compare before/after coverage
  34. Verify each test targets the intended function
  35. Check for test isolation/independence

Red Flags to Watch For

  • Tests that don't increase coverage
  • Overly complex test setups
  • Tests targeting multiple functions
  • Untested fixture setups
  • Missing error cases
  • Incomplete mock configurations

Questions to Ask

  • Am I actually testing the target function?
  • Does each test serve a clear purpose?
  • Are the mocks properly configured?
  • Have I verified the test infrastructure works?
  • Does the coverage report show improvement?
