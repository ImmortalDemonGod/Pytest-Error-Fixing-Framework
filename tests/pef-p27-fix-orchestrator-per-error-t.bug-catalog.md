# Bug Catalog — pef-p27-fix-orchestrator-per-error-t (F50, F51, F62)

- **Stale cross-error temperature in `get_progress()`** — `src/branch_fixer/orchestration/orchestrator.py:428-429`. `get_progress()` computes `current_temperature` as `self.initial_temp + self.temp_increment * self._session.retry_count`, where `retry_count` (`orchestrator.py:365`, `FixSession.retry_count`) is a **session-wide counter that accumulates across every error's retry loop and is never reset per error**. Meanwhile the *actual* temperature used inside `fix_error()` (`orchestrator.py:337`, `current_temp = self.initial_temp`) is reset to `initial_temp` at the start of every new error. Wrong: after error A fails N attempts and error B begins its first attempt (real temp = `initial_temp`), `get_progress()` reports `initial_temp + temp_increment * N` — a temperature that was never actually sent to the AI for error B. Correct: `current_temperature` must reflect the temperature in use for the *current* error's *current* attempt, i.e. it must be derived from a per-error attempt counter, not the global `retry_count`.

- **`run_session()` skips `failed_tests`/`passed_tests` update on early failure** — `src/branch_fixer/orchestration/orchestrator.py:248-254` vs `256-262`. When `self._handle_error_fix(error)` returns `False` for any error, `run_session()` immediately saves the session and `return`s (`orchestrator.py:250-254`) **before** reaching the count-computation block at `orchestrator.py:257-262`. Wrong: `session.failed_tests` and `session.passed_tests` are left at their dataclass defaults (`0`, `0` — see `FixSession.failed_tests`/`passed_tests` in the same file) even though one or more errors are demonstrably unfixed, so a persisted/saved session that failed early reports `0` failed tests. Correct: the failed/passed counts must be computed (or the early-return path must compute them) whenever the session terminates, whether it completes the loop or exits early on an irreparable error.

- **`FixService` is re-instantiated on every retry attempt instead of once per error** — `src/branch_fixer/orchestration/orchestrator.py:344-356`. The `FixService(...)` constructor call sits *inside* the `for attempt_index in range(self.max_retries)` loop in `fix_error()`, so a fresh `FixService` object is constructed for every single attempt (attempt 1, attempt 2, ... up to `max_retries`) rather than once for the whole error. Wrong: for an error that needs 2 attempts to fix, the constructor is called 2 times; for an error that exhausts `max_retries=3`, it is called 3 times. Correct: exactly one `FixService` should be constructed per error (outside/before the retry loop) and reused across that error's retry attempts.
