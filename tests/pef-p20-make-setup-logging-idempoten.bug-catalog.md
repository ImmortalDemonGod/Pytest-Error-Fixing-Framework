# Bug catalog — pef-p20-make-setup-logging-idempoten

- **Duplicate `snoop` FileHandler on repeated `setup_logging()` calls** — `src/branch_fixer/config/logging_config.py:30-37`. `setup_logging()` unconditionally constructs a new `logging.FileHandler` and appends it via `snoop_logger.addHandler(snoop_handler)` on every call, without first checking `snoop_logger.handlers` for an existing handler of the same type/target. Wrong: after N calls to `setup_logging()`, the `'snoop'` logger accumulates N `FileHandler` instances, so every log record emitted through it is written N times. Correct: `setup_logging()` is idempotent — after any number of calls, the `'snoop'` logger holds exactly the handler count it had after the first call (no duplicate handlers are appended).

- **Root cause is asymmetric with the root-logger handling on the same lines** — `src/branch_fixer/config/logging_config.py:14-24` vs `:30-37`. `logging.basicConfig(..., force=True)` (line 23) explicitly replaces the root logger's handler list on every call, making the root logger's handler setup idempotent by construction. The `'snoop'` logger block that follows has no equivalent replace-or-guard step. Wrong: only the root logger is protected against repeat-call duplication; the `'snoop'` logger is not, despite both being configured in the same function. Correct: the `'snoop'` logger's handler setup should have the same idempotency guarantee as the root logger's — either clear pre-existing `'snoop'` handlers before adding, or skip adding when an equivalent handler is already present.

- **Real-path double-invocation makes the defect certain to trigger in normal runs** — `setup_logging()` is called once in `src/branch_fixer/main.py` (`main()`) and again inside `fix()` in `src/branch_fixer/utils/run_cli.py`. Wrong: because `setup_logging()` is not idempotent, this ordinary two-call code path (not a misuse or edge case) leaves the `'snoop'` logger with 2 `FileHandler`s and every snoop log line duplicated in `logs/app.log`. Correct: with an idempotent `setup_logging()`, this same two-call path leaves the `'snoop'` logger with exactly 1 `FileHandler` and no duplicated log entries.
