# Bug catalog — pef-p06b-guard-transient-api (F88, F38)

- **Session-aborting retry loop (F88).** `src/branch_fixer/orchestration/orchestrator.py:357` — `FixOrchestrator.fix_error`'s `for attempt_index in range(self.max_retries)` loop calls `success = fix_service.attempt_fix(error, temperature=current_temp)` with no enclosing `try/except`. `FixService.attempt_fix` (`src/branch_fixer/orchestration/fix_service.py:104-167`) always converts an escaping exception — including a transient AI-provider `CompletionError` (rate limit, network timeout, invalid key) — into a raised `FixServiceError` via its outer handler at lines 165-167. Because the call at `orchestrator.py:357` is unguarded, that `FixServiceError` propagates straight out of `fix_error` on the very first attempt. **Wrong:** the entire autonomous fix session aborts on attempt 1, discarding the remaining `max_retries-1` retry slots. **Correct:** a `FixServiceError` raised by `attempt_fix` is caught at the call site, treated like a returned `False` (temperature bumped, `retry_count` incremented, loop proceeds to the next attempt), and `fix_error` only returns `False` after all `max_retries` attempts are exhausted.

- **Double-wrapped exception message discards its inner context (F38).** `src/branch_fixer/orchestration/fix_service.py:165-167` — the outer `except Exception as e` handler in `attempt_fix` computes `root_cause = getattr(e, "__cause__", e)` and raises `FixServiceError(str(root_cause)) from e`. When an inner handler (e.g. `fix_service.py:106-110`) has already raised a contextualized `FixServiceError(f"Workspace validation failed: {str(e)}") from e`, the outer handler's `e` IS that inner `FixServiceError`, so `e.__cause__` is the original raw exception (e.g. `OSError("no access")`) — `root_cause` unwraps PAST the inner handler's contextual prefix. **Wrong:** the final surfaced `FixServiceError` message is truncated to the bare inner-cause text (`"no access"`), losing the `"Workspace validation failed: "` prefix that explains what failed. **Correct:** the final surfaced `FixServiceError` message retains the full contextualized text produced by whichever handler raised it (`str(e)`, not `str(getattr(e, "__cause__", e))`), so a caller/log consumer sees `"Workspace validation failed: no access"`, not just `"no access"`.
